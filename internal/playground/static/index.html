    Catalog

    Addendum B · folders and placements in a catalog namespace
    Load a catalog namespace (the demo stack seeds cat, a tree, and topics, a DAG).

    Tree

    —

    Click a node to select it; item names open the item in the Resource tab. subject: role chips are the effective roles derived in this browser from $access on the node and its ancestors (§B.11.2); bold ones are assigned on the node itself. move/place mark tree powers where a role granting them is assigned (they are never inherited).

    Selected node

    Select a node in the tree.

    Move / reorder / remove

    PATCH or DELETE /r/{catalog}/{node}

    A move is one write to the moving node, guarded by If-Match (§B.2). Removing a placement leaves the content untouched; removing a folder does not cascade, its children become orphans (§B.7).

    New folder

    PATCH /r/{catalog}/{name} · If-None-Match: *

    Place item

    PATCH /r/{catalog}/{ns}.{name} · If-None-Match: *

    The placement's name is the item, {ns}.{name}, so an item is placed at most once per catalog (§B.2). A placement may name an item that does not exist yet; it is dangling until it does. Placements carry a fresh $nonce (§B.11.4).

    Last catalog write

    Writes go to the catalog namespace through the core API and also appear in the inspector.
